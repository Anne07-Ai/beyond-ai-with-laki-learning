What exactly is a token?

Illustrated learning guide · Concepts + diagrams + interview questions

The small pieces of text that language models read and write.

One-minute takeaway: Language models don't read text word by word the way we do. They work with tokens: small pieces of text that can be a whole word, part of a word or a punctuation mark. Tokens are the building blocks that language models use to process and generate text.

1. Think of building blocks

Imagine building something with Lego blocks. An AI model doesn't handle a whole sentence in one go. It works with smaller pieces of text, and those pieces are called tokens. This is a simplified analogy to make the idea easier to picture.

2. An example

A tokenizer might split “I love chocolate” into three tokens:

I ␣love ␣chocolate

The ␣ marks a space. Many tokenizers keep the space in front of a word as part of the token.

3. One token isn't always one word

Here's the surprising part:

  • A long or less common word can be split into smaller, more common pieces. For example, annoyingly might become annoying + ly.
  • Punctuation such as ? or . can be a token of its own.
  • The exact split depends on the model's tokenizer. Different models can split the same text differently.
Note: The splits on this page are illustrative. Real splits depend on the tokenizer. Inside the model, each token is stored as a number, not as letters.

4. Why does this matter?

Language models process tokens, not words exactly as we see them. When you ask ChatGPT a question, your text is converted into tokens. The model uses those tokens and the conversation so far to predict what comes next. It keeps generating tokens, one at a time, until it forms a response.

Your text → Tokens → Context → Next token → Repeat → Reply

Token counts are not word counts. Long words can become several tokens and punctuation can be its own token, so a sentence often has more tokens than words.

5. The context window: the model's desk

Every model has a context window: a limit on how many tokens it can work with at once.

Think of it like a desk. A bigger desk can hold more books and notes while you're working. A bigger context window can hold more information for the model to consider. The size varies from model to model.

6. See the process: text to model input

Think of a tokenizer as a bridge between human-readable text and the numbers a model operates on. The tokenizer divides text into units and looks up a token ID for each one. The model then represents those IDs as numerical vectors called embeddings and processes the sequence in context.

7. Why different tokenizers give different results

The tokenizer's vocabulary is a set of pieces it knows. A frequent word might stay as one piece, while a less common word might be divided into multiple parts. Tokenizers do not all share the same vocabulary or splitting rules.

Three important approaches are Byte Pair Encoding (BPE), which merges frequent pairs; WordPiece, which uses a different scoring strategy for merging; and Unigram, which scores candidate pieces and selects a suitable segmentation. You do not need to memorise the algorithms for Day 2, but they explain why token boundaries can vary. See the Hugging Face reference below.

8. What is a context window?

The context window is the amount of token-based information a model can consider within a request, including relevant conversation history and other input. The window is limited; as a conversation grows, applications may need to omit, summarise or retrieve information depending on their design. Do not assume a model remembers every earlier message forever.

9. Why token counts matter in real applications

  • Costs: Many hosted LLM APIs charge for input and output tokens. Pricing and cached-token rules vary by model.
  • Limits: Long prompts and large document inputs may exceed a model's or application's available token budget.
  • Latency: Generating more output tokens usually takes more processing time.
  • Prompt engineering: Concise, relevant context can be easier to manage than copying huge amounts of unrelated material.

For intuition only, an OpenAI guide uses roughly four English characters per token as a rough rule of thumb. This is not an exact conversion and should not be used as a technical guarantee for another language or tokenizer.

Try it yourself: Open the OpenAI Tokenizer and try punctuation, a long word, and the same sentence with changed spacing or capitalisation. Compare the boundaries; do not assume those boundaries match every model.

Knowledge check — quick quiz

  1. Is one token always one word?
    Answer: No. A token can be a whole word, part of a word or a punctuation mark.
  2. Who decides how text is split into tokens?
    Answer: The model's tokenizer. Different models can split the same text differently.
  3. What is a context window?
    Answer: The limit on how many tokens a model can work with at once, like the size of a desk.

Interview practice — beginner to AI engineer

Use these as short speaking answers, then try explaining each concept in your own words. The final questions explore production implications rather than just definitions.

1. What is a token in an LLM?

Answer: A token is a unit of text the model processes. It can be a whole word, part of a word, punctuation or another character sequence, depending on the tokenizer.

2. Is one token always equal to one word?

Answer: No. Tokenizers may keep a frequent word together or break a rarer word into multiple subwords. Spaces and punctuation also influence the split.

3. What does a tokenizer do?

Answer: It applies the model's tokenisation rules to transform text into a sequence of pieces and associated numerical IDs. Decoding maps generated IDs back into readable text.

4. What is the difference between a token ID and an embedding?

Answer: A token ID is a discrete index into the vocabulary. An embedding is a learned numerical vector representing that token for processing inside the model.

5. What is subword tokenisation, and why use it?

Answer: It represents text using pieces that can be smaller than full words. This makes it practical to handle uncommon or newly formed words using reusable pieces instead of requiring a separate vocabulary entry for every word.

6. How do BPE, WordPiece and Unigram differ?

Answer: BPE builds useful pieces by merging frequent pairs. WordPiece uses a different merge-scoring criterion. Unigram starts with candidate pieces and removes less useful ones according to a probabilistic model. They can create different splits.

7. What is a context window?

Answer: It is the bounded amount of token-based context that a model can consider for a request. Applications must manage that budget when handling conversation history, retrieved documents and other inputs.

8. Why do token counts matter in production?

Answer: They affect cost, latency, input limits and how much useful context fits into a request. We should measure token use with a tokenizer or provider counting endpoint appropriate to the target model.

9. How would you diagnose truncated or missing context in a RAG system?

Answer: Inspect input token counts, system/tool overhead, retrieved-chunk sizes, truncation policy and the model context limit. Log the assembled prompt metadata safely and test whether important evidence remains in the final context.

10. How should engineers estimate token-based inference cost?

Answer: Separate input, cached input and output token counts when the provider distinguishes them. Multiply actual usage by that model's current unit rates; account for retries, tool calls and any hidden or reasoning tokens reported by the provider.

Glossary — key words

Token: A piece of text a model works with: a word, part of a word or punctuation. Tokenizer: The model's method for splitting text into tokens. Subword: A piece of a longer or rarer word. Context window: The maximum number of tokens a model can take into account at once.
